# Bank Loan Risk Analysis

Проект по анализу кредитного портфеля банка с использованием PostgreSQL и SQL. Данные загружены напрямую в PostgreSQL и обработаны средствами SQL (очистка, проверка качества данных, аналитика). Экспорт аналитических представлений в CSV автоматизирован Python-скриптом.
В проекте выполнены очистка данных, исследовательский анализ, сегментация клиентов по кредитному риску и создание аналитических представлений (Views). Результаты визуализированы в виде интерактивного дашборда в Tableau.

## Цели проекта

- Очистить исходный набор данных о банковских кредитах.
- Проанализировать структуру кредитного портфеля и клиентской базы.
- Выявить факторы, влияющие на просрочки и дефолты по кредитам.
- Провести сегментацию клиентов по уровню кредитного риска.
- Закрепить навыки работы с SQL в PostgreSQL, включая оконные функции и CTE.
- Создать проект для портфолио Data Analyst.

### 📁 sql

- **01_create_database.sql** — создание базы данных.
- **02_create_tables.sql** — создание таблицы `loans` и промежуточной staging-таблицы `loans_raw` (используется для корректной загрузки "грязных" текстовых значений вроде `NA` перед конвертацией в числовой тип).
- **03_data_quality.sql** — проверка качества данных: пропуски, дубли по Loan ID, аномалии Credit Score.
- **04_data_cleaning.sql** — очистка данных и создание представления `loans_clean` (дедупликация, исправление выбросов, нормализация категорий).
- **05_basic_analysis.sql** — базовые бизнес-метрики и обзор портфеля.
- **06_risk_analysis.sql** — анализ факторов риска: Credit Score, долговая нагрузка, история просрочек, стаж, тип жилья.
- **07_cte.sql** — примеры использования Common Table Expressions (CTE): риск-сегментация, сравнение с портфельным средним, риск по комбинации факторов.
- **08_window_functions.sql** — оконные функции: `RANK()` для ранжирования кредитов внутри цели кредита, `NTILE()` для квартилей дохода, накопительная сумма портфеля через `SUM() OVER`, сравнение кредита со средним по риск-сегменту через `AVG() OVER (PARTITION BY ...)`.
- **09_views.sql** — создание 5 представлений (VIEW) для дашборда.
- **10_final_queries.sql** — итоговые аналитические запросы проекта.

### 📁 python

- **export_views.py** — подключается к PostgreSQL и выгружает все аналитические VIEW в CSV-файлы в `data/processed/` для последующей загрузки в Tableau.

## Датасет

В проекте используется открытый датасет **Bank Loan Status Dataset** (Kaggle), содержащий данные о выданных банком кредитах и их текущем статусе.

Основные поля датасета:

- Loan ID — идентификатор кредита;
- Customer ID — идентификатор клиента;
- Loan Status — статус кредита (Fully Paid / Charged Off);
- Current Loan Amount — сумма кредита;
- Term — срок кредита;
- Credit Score — кредитный рейтинг клиента;
- Annual Income — годовой доход;
- Years in current job — стаж на текущем месте работы;
- Home Ownership — тип владения жильём;
- Purpose — цель кредита;
- Monthly Debt — ежемесячные долговые обязательства;
- Years of Credit History — длина кредитной истории;
- Months since last delinquent — месяцев с последней просрочки;
- Number of Open Accounts — количество открытых счетов;
- Number of Credit Problems — количество кредитных проблем;
- Current Credit Balance — текущий баланс задолженности;
- Maximum Open Credit — максимальный открытый кредитный лимит;
- Bankruptcies — количество банкротств;
- Tax Liens — налоговые залоги.

### Проблемы качества данных, обнаруженные и исправленные

- **Дублирование записей**: каждый Loan ID встречался дважды — одна копия с пустыми `credit_score`/`annual_income`, вторая с заполненными значениями. Оставлена только заполненная версия (`SELECT DISTINCT ON` с сортировкой по заполненности).
- **Мусорные строки**: 514 полностью пустых строк с пустым Loan ID — удалены.
- **Аномалия Credit Score**: часть значений записана с лишним нулём (диапазон встречался до 7510 вместо корректного 300–850) — исправлено делением на 10 с последующим округлением.
- **"Магическое число"-заглушка**: около 9 700 записей имели `Current Loan Amount = 99 999 999` вместо реального значения — такие записи исключены из витрины.
- **Разнобой в категориях**: `"other"` / `"Other"`, `"HaveMortgage"` / `"Home Mortgage"`, подчёркивания вместо пробелов (`Small_business`) — нормализовано в единый читаемый формат.
- **Текстовые заглушки `"NA"` в числовых полях**: обработаны через промежуточную таблицу `loans_raw` (все поля текстом) с последующей конвертацией через `NULLIF(...)::NUMERIC`.

## Основные этапы анализа

### 1. Создание базы данных
Создание таблицы `loans` для хранения данных о кредитах, настройка структуры в PostgreSQL.

### 2. Подготовка данных
Импорт исходного файла через pgAdmin, обработка проблемных текстовых значений через staging-таблицу.

### 3. Проверка качества и очистка данных
Поиск пропусков, дубликатов, аномальных значений; создание очищенного представления `loans_clean`.

### 4. Исследовательский анализ
Структура портфеля, клиентская база, распределение по целям кредита и статусу.

### 5. Анализ рисков и просрочек
Связь Credit Score, долговой нагрузки, истории просрочек и стажа со статусом кредита.

### 6. Продвинутый SQL
- Common Table Expressions (CTE) — многошаговая риск-сегментация.
- Оконные функции — `RANK()`, `NTILE()`, накопительные суммы, сравнение строки со средним по партиции.
- Представления (Views) — пятислойная витрина под дашборд.

### 7. Сегментация по кредитному риску
Расчёт риск-сегментов на основе Credit Score (Low / Medium / High / Unknown Risk), профилирование сегментов по дефолту.

### 8. Финальные аналитические запросы
Структура портфеля, топ факторов риска дефолта, профиль клиентов по риск-сегментам и квартилям дохода.

## Дашборд (Tableau Desktop)

Интерактивный дашборд на основе CSV-выгрузок из аналитических SQL-представлений, состоит из двух страниц.

### Страница 1 — Overview (обзор портфеля)
- Количество кредитов по статусу (Fully Paid / Charged Off)
- Сумма кредитов по цели (Purpose)
- Количество кредитов по типу владения жильём (Home Ownership)

### Страница 2 — Risk Analysis (риск-анализ)
- Доля дефолтов по риск-сегментам (Low / Medium / High / Unknown Risk)
- Доля дефолтов по квартилям дохода
- Heatmap: концентрация кредитов по комбинации цели кредита и типа жилья

🔗 Дашборд: `dashboard/bank_loans_dashboard.twbx`

## Ключевые выводы

- Кредитный скоринг — самый сильный предиктор дефолта: доля просрочек падает с 48.6% у клиентов с низким скорингом (< 600) до 7.8% у клиентов с высоким скорингом (750+).
- Долговая нагрузка (Debt-to-Income) также сильно коррелирует с риском: от 22% дефолта при низкой нагрузке (<10%) до 43% при высокой (>35%).
- Отсутствие данных о скоринге само по себе является маркером повышенного риска: у клиентов без указанного Credit Score дефолт выше среднего по портфелю (36.3% против 30.6%).
- История прошлых просрочек и стаж работы клиента практически не влияют на вероятность нового дефолта — вопреки интуитивному ожиданию (30.57% vs 30.53% дефолта с историей просрочек и без).
- Самый рискованный профиль клиента — цель "Small Business" в комбинации с арендой жилья (55.2% дефолта), самый надёжный — ипотечники с высоким скорингом (23.7% дефолта).
- Датасет не содержит повторных обращений одного клиента за кредитом — каждый Customer ID связан ровно с одним Loan ID.
